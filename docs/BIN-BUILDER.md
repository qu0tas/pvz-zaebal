# Локальный экспериментальный генератор BIN

## Поддерживаемый сценарий

GitHub Pages / современный браузер с Web Crypto → три **точных оригинальных** EBX BIN из поддерживаемой выгрузки GW2 → выбор десяти штатных групп/составов и существующих точек → ZIP с тремя BIN, инструкцией, отчётом и планом. Никакой загрузки игровых файлов на сервер, backend, .NET-сервиса или генерации FBMOD нет.

По запросу владельца пять пар оригинальных BIN/XML включены в `originals/`. Три требуемых BIN также встраиваются в HTML в base64 при сборке и проверяются автоматически при открытии страницы. Повторная ручная загрузка не нужна; кнопка восстановления возвращает встроенные копии после очистки. Манифест всех десяти файлов: `originals/manifest.json`. Они публично доступны вместе с сайтом; проверь права перед публикацией. Хранение ChallengeSelector и RewardSpin не включает их редактирование. Названия: `AISpawnGrid.bin`, `GardenOps_WaveTree.bin`, `GardenOps_WaveLogic.bin`. Размеры и SHA-256 — `data/bin-schema.json` → `files` и `reference/game-originals-manifest.json`. Если новый экспорт Frosty отличается, генератор его **отклоняет**, а не пытается патчить по старым смещениям. Несовпадение не означает вредоносность/порчу: возможна другая версия или сериализация.

Не загружай Test04–Test07 или ранее изменённые BIN. Для Web Crypto используй GitHub Pages по HTTPS либо localhost; поддержка `file://` зависит от браузера. Рабочие буферы держатся в памяти вкладки. Очистка освобождает рабочие копии, но не удаляет встроенные данные из HTML; перезагрузка или кнопка восстановления снова проверяет их. Скачанные файлы сохраняются обычным механизмом браузера.

## Пользовательский процесс

1. Выбрать все 10 волн. Для каждой — штатный выбор состава или конкретный состав.
2. Назначить существующие точки либо оставить «Авто». «Авто» не означает фиксированный спавн.
3. Снять AMBUSH!!!: эта настройка пока не поддерживается записью BIN и блокирует сборку.
4. Открыть «Собрать BIN» и дождаться статуса 3/3: сайт автоматически проверит размер, SHA-256 и структуру встроенных оригиналов. При необходимости можно выбрать поддерживаемые оригиналы вручную.
5. Подтвердить экспериментальный статус и скачать ZIP.
6. Создать отдельный Frosty-проект, импортировать три ресурса по инструкции, сохранить, экспортировать XML и проверить назначения.
7. Экспортировать FBMOD средствами Frosty, отключить конфликтующие старые версии и проверить в разрешённом личном тесте Time Park.

Результат не откатывает изменённые ChallengeSelector/RewardSpin из старого проекта. Используй чистый отдельный проект для воспроизводимого теста.

## Содержимое ZIP

- `AISpawnGrid.bin` — добавленные интерфейсные константы и property bindings только для выбранных явно A-точек; без перемещения геометрии.
- `GardenOps_WaveTree.bin` — выбор состава, экспериментальные UseSpecificSpawnID, одна основная точка на назначенную подгруппу и расширенные дистанционные фильтры.
- `GardenOps_WaveLogic.bin` — существующие маршруты запуска волн 1–10 направлены на выбранные группы. Служебный маршрут волны 11 сохранён.
- `README_IMPORT_RU.txt` — точные пути, порядок проверки, ограничения, таблица назначений.
- `build-report.json` — хеши входов/выходов, список назначений с GUID/координатами, выбранные узлы, проверки и предупреждения.
- `plan.json` — снимок плана с текущей разметкой для повторного импорта.

## Что НЕ поддерживается

Создание дополнительных спавнеров, перенос игровых координат, произвольные новые противники/количества, другие карты/профили/версии BIN, AMBUSH-вступление, отключение случайных задач, гарантированные денежные выплаты и сборка FBMOD. Интерфейс меняет существующие варианты волн, а не создаёт новые игровые классы.

Самое важное: генератор использует **экспериментальный метод 100xx**, который прежде сохранялся в корректном XML, но не гарантировал нужный спавн в игре. Исправление фоторазметки не решает этот вопрос автоматически. Не называй результат «проверенный рабочий мод».

## Архитектура

- `src/bin-panel.html`: загрузчик и согласие на экспериментальный статус.
- `src/bin-builder.js`: SHA-256, проверка плана, запись BIN, проверки, ZIP stored/CRC32.
- `data/bin-schema.json`: только смещения, типы, GUID, hash-события и сведения о точных baseline-файлах; без полезной нагрузки оригинальных игровых BIN.
- `scripts/generate_bin_schema.py`: восстановление схемы из трёх локальных оригиналов и каталога.

```bash
python scripts/generate_bin_schema.py local-game-files --check
python scripts/build.py
python scripts/build.py --check
python -m unittest discover -s tests -v
node tests/bin_builder.cjs
```

Регистрация точек переносит два массива grid в конец файла, добавляет строки с Int32-константами, обновляет string length, offsets, counts, padding и общий размер. WaveTree не удаляет 147 корневых групп; конкретный состав сужает только массив Waves выбранной группы. Общая подгруппа не может получить конфликтующие назначения. Неиспользуемые служебные маршруты не перенаправляются.

Не переносить смещения схемы на другой исходник и не отключать проверку SHA-256 ради «совместимости». Для расширения поддерживаемых версий нужен отдельный профиль, независимое чтение результатов, регрессионные тесты и тест в игре.

## Проверки

Python-тесты проверяют репозиторий и схему. Node-тесты используют собственные синтетические буферы, а не игровые ресурсы. Есть проверки CRC32/SHA-256, планов, auto, конкретного состава, ID и сохранения служебных событий.

При разработке проведён браузерный прогон на реальных локальных оригиналах: загрузка/скачивание, 301 комбинация каталога/состава (включая сохранение служебных записей), отказ при неизвестном SHA, неполном плане и AMBUSH. ZIP распакован и проверен независимым Python zipfile, три результата прочитаны отдельным EBX-reader. Для исторического плана три BIN побайтово совпали с прежней независимой Python-сборкой Test05. Это **доказательство эквивалентности записи**, а не правильности её игрового метода.

Основной браузерный smoke-test использует встроенные оригиналы; необязательный `--originals DIR` проверяет также ручную замену:

```bash
# Дополнительно нужен Python Playwright и доступный Chromium.
python scripts/browser_smoke.py --browser /path/to/chromium
```

Smoke-test использует исторический регрессионный план из reference, **не рекомендуемый игровой паттерн**. Выходы помещаются в игнорируемую `artifacts/`. CI проверяет предоставленные оригиналы и включает их в статический сайт, но не запускает игру. При `--output _site/index.html` сборщик также копирует папку `originals/` в `_site/originals/`.

Проверено для встроенных оригиналов: автоматическая загрузка, очистка/восстановление, повторное открытие, ZIP без ручной загрузки, отказ при повреждённом встроенном BIN и неизвестной ручной замене. Это не игровой тест.
