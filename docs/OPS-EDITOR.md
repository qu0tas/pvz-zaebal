# Текущий редактор двух режимов

## Структура

- `index.html`: Garden, 147 корневых групп, 942 EventConnections WaveLogic, 271 распознанный маршрут запуска.
- `graveyard.html`: Graveyard, 105 корневых групп, 737 EventConnections, 183 распознанных маршрута. Вступление `Wave00` имеет исходный WaveNumber=1, но выделено как служебное; его маршрут помечен wave=0 и сохраняется.
- `data/catalog.json` / `graveyard-catalog.json`: каталоги для UI. Служебные группы не доступны как обычные волны.
- `data/garden-profile.json` / `graveyard-profile.json`: точные хеши пяти оригиналов, смещения полей/массивов и карты событий.
- `scripts/generate_ops_profiles.py`: воспроизводимое построение профилей из проверенных оригиналов. Для растений используется XML для путей/названий и BIN для смещений. Переводы справочные; внутренние имена сохраняются.
- `scripts/build.py`: строит обе страницы, встраивает фотографии, каталог, выбранный профиль и пять BIN. При `--output _site/index.html` пишет также `_site/graveyard.html` и копирует `originals/`.
- `src/app.js`: отдельные ключи автосохранения, валидация режима, формы и текстовый JSON.
- `src/bin-builder.js`: патчер, проверки входов/выходов и stored ZIP с CRC32, без backend.

## Формат плана v1 (расширенный, совместимый с прежним Garden)

`format=gw2-timepark-plan`, `version=1`, `mode=garden|graveyard`, `name`, `waves`, `enemyLimits`, `ops`.

`waves[1..10]`:
- `groupGuid`: GUID существующей группы текущей волны/режима.
- `compositionGuid`: `auto` либо GUID состава из этой группы.
- `assignments`: GUID подгруппы → `auto` либо доступная метка Axx.
- `delay` (необязательно): число 0..300 секунд; пишет StartDelayTime. Отсутствие сохраняет исходное значение.
- `ambush`: старое поле плана. `true` блокирует BIN-сборку, потому что безопасное изменение всей цепочки вступления не реализовано.

`enemyLimits[subgroupGuid][index] = {"min": 1, "max": 3}`. Индекс — порядок записи в `WaveSpawnTypeSet`, не произвольный тип врага. Целые значения 0..500, min≤max. Изменения невыбранных подгрупп могут храниться в плане, но применяются только к подгруппам активных составов. Общая подгруппа — одно общее изменение. MaxTotalCount, pool и прочие лимиты не меняются.

`ops.challenge`: `vanilla`, `NoKnockouts`, `NoBaseDamage`, `NoPlayerDamage`.

`ops.reward.mode`: `vanilla`, `silver`, `bag`, `gem`, `moneyOnly`, `custom`.

`ops.reward.weights`: целые относительные веса `silver`, `bag`, `gem`, `horde` в 0..1000. Для custom хотя бы один положительный. WG01 не содержит horde-выхода: вариант «только horde» отклоняется, а не подменяется. Веса нормируются отдельно по доступным исходам каждой ветки.

Старый план без mode считается Garden только при совпадении GUID его каталога; нет автоматического переноса врагов/групп в Graveyard. Неизвестный режим/неверные поля не должны молча превращаться в другую сборку. Существующие неизвестные/исключённые метки импортёр переводит в auto с пояснением.

## Общие ресурсы

Selector один и тот же по GUID для обоих режимов. В нём 171 EventConnections. Перенаправляются только 20 запросов от интерфейса, кроме reset; копируются Target и TargetEvent существующей ветки. Все callback/lifecycle-связи и остальные объекты остаются оригинальными. Это **не отключение задач**; боковые задачи могут инициироваться и вне этого префаба.

BossWave ссылается на общий RewardSpin с совпадающим GUID. В RewardSpin 37 EventConnections, они не меняются. Меняются только UniformDistribution и 10 Float-весов в двух RandomMultiEvent-объектах:

| Ветка | coinGem | coinBag | coinSilver | Пустой / horde |
|---|---|---|---|---|
| WG01 | Out0..4 | Out5..8 | Out9 | нет |
| WG02 | Out0..3 | Out4..6 | Out7..8 | Out9 |

Соответствия восстановлены по исходным ссылкам и StringProperties; игровой результат и выплата не подтверждены. Серебро: 100% суммарного веса только у coinSilver в обеих ветках, horde=0. Число денежных символов определяется выбранной SlotsCoopWaveGroup; RewardSpin не заменяет её боссовые иконки/врагов. TeaseSelector/анимация вращения и сумма наград не патчатся.

## Что получаем в ZIP

Пять BIN выбранного режима + инструкция, отчёт с хешами/путями/изменениями и снимок плана. Неизменённые общие BIN тоже включаются для отката предыдущих правок. Слои карты, дополнительные специальные префабы и BossWave не выдаются как изменённые, потому что редактор их не патчит. Не включать два конфликтующих мод-пакета одновременно.

## Проверки и пределы

`tests/ops_profiles.cjs` реально генерирует пять файлов на оригиналах для обоих режимов и прогоняет 530 сочетаний групп/составов. Результаты только в `artifacts/`.

`scripts/verify_generated.py FOLDER` независимо читает исходные и полученные BIN и сравнивает полные семантические объекты с ожидаемыми изменениями: дерево, все маршруты, lifecycle Selector, веса RewardSpin, исходные/новые привязки grid. `scripts/browser_ops_smoke.py` проверяет формы, JSON, ZIP, CRC/SHA, повторное открытие, размеры экрана и прежние три Garden-хеша.

Внешний Frosty roundtrip новой версии не выполнен. Применимость grid к Graveyard, переходы волн, отсутствие побочных волн, настоящее число врагов и выплаты нужно проверять в игре. Исправления разметки Рима/Центра — отдельное доказательство, не runtime-доказательство метода ID.
