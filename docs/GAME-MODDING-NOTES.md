# Передача контекста по Frosty / спавнам

## Состояние задачи

Игра: Plants vs. Zombies Garden Warfare 2; Frosty Editor на скриншотах — 1.0.6.3. Цель пользователя: воспроизводимые десять волн Garden Ops на Time Park у египетского сада, фиксированные места появления, босс + две монеты в колесе.

Сайт описывает план; генерация готового мода не входит в этот репозиторий. Последняя подтверждённая проверка Test07: все пять экспортов после импорта содержали ожидаемые значения. После игрового теста пользователь всё равно сообщил о неправильных местах появления. Затем проверка координат выявила ошибки разметки Рима/Центра; исправлен только сайт. **Не утверждать, что игровая проблема уже решена.**

## Ресурсы

- `Levels/Level_Coop_TimePark/AISpawnGrid`: SubWorldData, не подменять им layer0.
- `Levels/Level_Coop_TimePark/aispawngrid/layer0_aispawns`: размещённые обычные спавнеры.
- `Levels/Level_Coop_TimePark/aispawngrid/layer1_epicspawns`: пять эпических точек.
- `Levels_Sandbox/Level_Shawbs_Sandbox/GardenOps/GardenOps_WaveTree`.
- `Levels_Sandbox/Level_Shawbs_Sandbox/GardenOps/GardenOps_WaveLogic`.
- `Levels_Sandbox/Level_Shawbs_Sandbox/CoOps/CoOps_AISpawn_Prefab`.

- `Levels_Sandbox/Level_Shawbs_Sandbox/CoOps/CoOps_SlotMachine_RewardSpin`.

Регистр и отображение папок сверять в реальном Frosty. Манифест оригиналов содержит известные пути, размеры и SHA-256. Полные ресурсы намеренно отсутствуют.

## История экспериментов, не рецепты гарантированного исправления

- Test04: метод с семью привязками точек и экспериментальными ID 100xx; первые две волны пользователь считал корректными.
- Test05: тот же метод для последнего плана, 13 точек / 22 подгруппы. Проблемы спавнов и дополнительные задания оставались.
- Test06: 55 регистраций с ID 0–54 и мгновенное завершение 20 запросов заданий. Пользователь сообщил о старых неверных спавнах, старте волны до таймера и зависании таймера. Не повторять как «исправление».
- Test07: спавны/WaveLogic побайтово как Test05; вместо мгновенного завершения — перенаправление запросов в штатную NoKnockouts. Ветки жизненного цикла сохранялись. Это не полное отключение заданий; условие «без потерь» может отображаться. Параметры двух серебряных монет остались экспериментальными, выплата не подтверждена.
- Повторяющиеся старые экспорты оказались реальным выбором BIN из папки Test06, что показал лог импорта. Позже правильные Test07-экспорты прошли проверку; это не устранило игровые сомнения.

Старый план до исправления визуальных меток: 1 A22/A54; 2 A12/A30; 3 A10/A54/A53; 4 A31/A18; 5 A22/A15/A23; 6 A30/A55; 7 A10/A47; 8 A54/A15; 9 A53/A24; 10 A12/A31. **Не превращать этот список в новый мод без повторного подтверждения мест на исправленной карте.** Пользователь согласился на две точки волны 6.

Выбранные узлы: Wave01-1, Wave02-1, Wave03-SW_Imps, Wave04-SW_Ambush, Wave05-GargHorde, Wave06-1, Wave07-1, Wave08-SW_Science, Wave09-SW_Welders, Wave10-RoboHorde.

## Технические находки

- Все 147 корневых WaveGroups сохранять в исходном порядке. Удаление/сжатие групп ранее приводило к проблемам перехода волны 3.
- Идентификатор события запуска — hash `Start_` + NodeName, не индекс массива. Использовался DJB2-xor: старт 5381, `h=((h*33)^ord(c)) & 0xffffffff`.
- В WaveLogic было 942 EventConnections; 253 групповых запуска перенаправлялись на выбранные группы без изменения остальных переходов.
- В оригинальном WaveTree все UseSpecificSpawnID были −1. Подтверждённого ванильного примера положительных ID и требования диапазона 0..54 нет.
- Prefab interface field `0x93fc517f` передаёт значение в native `SpawnerID` `0x8a368144`; выбранные внешние bindings экспериментально добавлялись с Flags `0x11`, как существующие instance bindings. Наличие binding в XML не доказывает применение в рантайме.
- Prefab `Enabled = 0x28a000`; `0xc0fedf97` — IsEpicSpawnPoint, **не Enabled**.
- Ветка `0xbad9f704` ChallengeSelector — NoKnockouts, не «нет задания»; её целевой input `0xb66f2d3e`. Output `0x5a425b29` использовался как продолжение; непосредственный вызов из входа Test06 был неподтверждённым и проблемным.
- Канальное поле `0xf4fc5155` — PlayerCount, не номер волны.
- `assorted` в слотах — случайный денежный слот. Строка значка сама по себе не устанавливает выплату. В RewardSpin два RandomMultiEvent были принудительно направлены на свои серебряные исходы (индексы 9 и 8 соответственно); не переносить индексы вслепую в другую структуру файла.
- Штатный радиус и alternate positions спавнера сохранены; центр точки не равен точной позиции каждого отдельного противника.

## Независимая проверка

1. Сохранять оригиналы отдельно, записывать хеш входов/выходов и перечень изменений.
2. После импорта экспортировать XML из текущего проекта. Сверять все GUID размещений, ID, выбранные композиции и подгруппы, параметры, связи событий.
3. Не сравнивать неэкспортируемые временные XML-GUID буквально: при повторной сериализации они перенумеровываются. Сопоставлять по типу и Blueprint/Channel, проверять уникальность соответствия.
4. Сохранить проект, экспортировать новый FBMOD, заменить старый активный мод, исключить конфликтующие версии.
5. Только после этого тестировать в разрешённой среде. Фиксировать волну, ожидаемую метку, фактические X/Y/Z и ориентир. «Зомби подошли с другой стороны» не всегда означает другой спавн.
6. Если несколько одинаковых неудач повторяются, не выпускать очередной архив с угаданными ID. Изменить диагностический подход.

## Ограничения EBX reader

`scripts/ebx_inspect.py` читает использовавшийся legacy magic `0x0fb2d1ce`, таблицы, ссылки и распространённые типы. Неизвестные типы помечаются `unparsed_type`; результат не является точным round-trip для переписывания rich structures. Проверять границы, поддерживаемую версию и входные файлы. Скрипт не выполняет игровых команд и не патчит античит.
