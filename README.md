# Time Park — планировщик Garden Ops

Статический сайт для Plants vs. Zombies: Garden Warfare 2: выбрать варианты десяти волн, назначить подгруппам точки на фотографиях Time Park и скачать план JSON.

**Теперь есть экспериментальный генератор трёх BIN.** Он обрабатывает загруженные оригиналы локально в браузере. FBMOD по-прежнему собирается вручную во Frosty; правильные спавны в игре не гарантируются. Точки `A01–A55` — наши обозначения размещений, а не штатные SpawnID.


## Собрать BIN в браузере

1. Выбери все 10 волн и существующие точки. Сними AMBUSH!!! — запись этого вступления пока не реализована.
2. Нажми **«Собрать BIN»** и загрузи поддерживаемые оригинальные `AISpawnGrid.bin`, `GardenOps_WaveTree.bin`, `GardenOps_WaveLogic.bin`.
3. После проверки SHA-256 подтверди экспериментальный статус и скачай ZIP.
4. В ZIP будут три BIN, инструкция импорта, отчёт с хешами и снимок плана. Сам FBMOD экспортируется средствами Frosty Editor.

Файлы остаются внутри браузера. Неизвестные версии и старые изменённые BIN отклоняются. Генератор **не создаёт новые точки, не двигает игровые спавнеры, не редактирует произвольные количества врагов и не отключает случайные задания/не фиксирует выплаты колеса**. Метод фиксированных ID остаётся экспериментальным. Подробности и ограничения: [docs/BIN-BUILDER.md](docs/BIN-BUILDER.md).

## Быстро опубликовать на GitHub

1. Распакуй архив. Загрузи **содержимое папки `timepark-planner` в корень репозитория**, а не сам ZIP. В корне должны оказаться `index.html`, `README.md`, `src/`, `data/`, `assets/`, `scripts/` и `.github/`.
2. Для самого простого варианта: **Settings → Pages → Deploy from a branch → main → /(root) → Save**. Готовый `index.html` уже включён в архив.
3. Для автоматической проверки и публикации выбери вместо этого **Settings → Pages → Source: GitHub Actions**. В репозитории есть `.github/workflows/pages.yml`.
4. Для Actions основная ветка должна называться `main`; если у тебя другое имя, измени `branches` в workflow. При необходимости разреши Actions в настройках репозитория.
5. Дождись успешной публикации. Точный адрес покажет GitHub в Settings → Pages или в задании Deploy.

Если обновляешь существующий репозиторий, сначала сохрани старую версию/создай отдельную ветку. Не удаляй свои `CNAME`, домен и настройки Pages: в этом архиве их нет. Этот пакет подготовлен для обновления `qu0tas/pvz-zaebal`; удалённый репозиторий из этого чата не изменялся.

> При загрузке через веб-интерфейс GitHub проверь, что папка `.github` тоже попала в репозиторий. При режиме публикации из ветки Actions не обязателен.

## Открыть без GitHub

Открой `index.html` в браузере. Все фотографии и данные встроены; сервер и интернет для работы страницы не нужны. План сохраняется в localStorage браузера, но надёжная переносимая копия — кнопка **«Скачать план JSON»**. При другом адресе сайта, браузере или origin автосохранение может не перенестись: загрузи JSON кнопкой **«Загрузить план»**.

## Что исправлено

Фоновые фотографии **не отражались, не вращались и не заменялись**.

- **Рим:** A02 ↔ A49; A23 перенесена к красной отметке пользователя; A34 сохранена.
- **Центр:** A10 ↔ A15, A55 ↔ A01, A54 ↔ A31, A47 ↔ A24, A12 ↔ A53, A30 ↔ A09, A18 ↔ A11. A22 оставлена на месте.
- **Египет и Китай:** без изменений. Правильность всех их меток в игре отдельно не подтверждена.
- Номера точек, GUID и мировые координаты не менялись. Изменились только позиции значков на фотографиях.
- В экспортируемом плане: `placementMap = user-screenshots-rome-center-corrected-v3`.

Импорт старого плана **не переназначает** выбранные номера точек. Если места выбирались по старой разметке, проверь/перевыбери точки на исправленных фотографиях и скачай новый JSON.

## Структура

## Изменить сайт

Для сборки нужен **Python 3.10+**, сторонние пакеты не нужны. Для синтетических JS-тестов — Node.js 20+ без npm-пакетов.

```bash
python scripts/build.py
python scripts/build.py --check
python -m unittest discover -s tests -v
node tests/bin_builder.cjs
```

Изменяй `src/`, `data/` и при необходимости `assets/`, затем пересобирай `index.html`. Коммить и исходники, и актуальный `index.html`. Команда `--check` намеренно падает, если собранная страница устарела.

Локальный HTTP-просмотр:

```bash
python -m http.server 8000
```

Открой `http://localhost:8000/`. Для работы с JSON сервер не обязателен.

### Быстро исправить метку

В `data/photo-layout.json` найди зону и точку. Меняй **только `x` и `y`** позиции на фотографии: диапазон 0–1, X направо, Y вниз. Не меняй `id`, `guid` и `world` ради перемещения значка. Для обмена местами двух меток обменяй обе пары `x/y`; не отражай фон через CSS.

После сознательной новой правки обнови версию `placementMap` в `src/app.js`, описание и соответствующий регрессионный тест. Не переписывай исходный эталон в `reference/original-site/`, чтобы «починить» падающий тест. См. [инструкции для агентов](AGENTS.md).

## Оригинальные игровые файлы

Найдены и описаны 14 исходных экспортов, включая WaveTree, WaveLogic, AISpawnGrid, layer0/layer1, CoOps_AISpawn_Prefab, ChallengeSelector, RewardSpin и BossWave. Их происхождение и SHA-256 — в `reference/game-originals-manifest.json`.

Полные выгрузки игры не включены в публичный пакет. Экспортируй нужные ресурсы из своей копии через Frosty и положи в `local-game-files/`. Папка защищена `.gitignore`, но перед любым push всё равно проверь staged files. Другая версия игры/экспорта может иметь другие байты: несовпадение SHA-256 не доказывает повреждение.

```bash
python scripts/check_originals.py local-game-files
# Необязательная экспериментальная диагностика legacy EBX:
python scripts/ebx_inspect.py local-game-files/AISpawnGrid.bin local-game-files/AISpawnGrid.decoded.json
```

EBX-reader — небольшой проверенный на одном исходнике диагностический помощник, **не полный SDK Frosty**, не генератор модов и не универсальный парсер всех версий.

## Что проверено / что не проверено

- Проверены воспроизводимая сборка, автоматические Python/JS-тесты, импорт/экспорт плана и выбор точки в браузере.
- Проверены Рим/Центр на большом экране и адаптация Рима на узком экране; фоновые изображения и GUID/world совпадают с предыдущим сайтом.
- Исправление разметки основано на проверке и отметках пользователя. Это **не доказательство**, что ID спавнера применяется движком.
- У Test07 импорт в Frosty был подтверждён по XML, но пользователь затем сообщил о неверных спавнах. Новый генератор воспроизводит экспериментальную запись BIN, но исправленной и проверенной в игре сборки здесь по-прежнему нет.
- Файл скилла написан и сверён с устройством репозитория; отдельный тест другим агентом не запускался.

## Права и безопасность

Неофициальный фанатский инструмент, не связан с EA/PopCap. Названия игры и скриншоты относятся к соответствующим правообладателям. Широкая лицензия на чужие игровые материалы в пакет не добавляется; перед публичным размещением проверь право на использование изображений.

Не коммить игровые выгрузки, ключи, токены, персональные пути и файлы проекта Frosty. Не отключай античит и не используй диагностические изменения на официальных соревновательных серверах. Примеры исследования спавнов относятся только к разрешённой личной/пользовательской тестовой среде.
