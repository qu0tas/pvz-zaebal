# Time Park — редактор Garden Ops и Graveyard Ops

Два статических редактора для Plants vs. Zombies: Garden Warfare 2. Выбирай штатные варианты 10 волн, существующие точки Time Park, лимиты записей противников, задержки, денежные результаты колеса и обработку запросов испытаний. Редактируй план через формы или JSON. Оригинальные BIN проверяются автоматически; обработка выполняется в браузере.

**Это экспериментальная запись BIN, не подтверждённый рабочий мод.** Игра здесь не запускалась. Корректный BIN/XML не доказывает нужные спавны, награды и переходы волн. FBMOD экспортируется вручную во Frosty Editor.

## Быстрый запуск

1. Открой `index.html` (**Garden Ops**) или `graveyard.html` (**Graveyard Ops**). На опубликованном сайте режим выбирается сверху. Для Web Crypto рекомендуется GitHub Pages HTTPS или localhost; `file://` проверен в Chromium, но зависит от браузера.
2. Выбери варианты всех 10 волн, составы и точки. В раскрываемых лимитах можно менять min/max существующих записей. Поле задержки меняет `StartDelayTime` группы, не всю цепочку таймеров.
3. Настрой **«Колесо и испытания»**. Для двух монет выбери на волне 5/10 вариант **«1 босс + 2 денежных слота»** и результат **«Только серебряная монета»**. Нужный вариант выбирается в самом списке волн, не только в настройке RewardSpin.
4. Открой **«Собрать BIN»**, дождись проверки **5/5**, подтверди экспериментальный статус и скачай ZIP.
5. В отдельный чистый проект Frosty импортируй **все пять BIN** из ZIP по вложенной инструкции. Сохрани, экспортируй XML для проверки; затем собери FBMOD и проверь в разрешённом личном тесте.

В ZIP: `AISpawnGrid.bin`, WaveTree и WaveLogic выбранного режима, `CoOps_ChallengeSelector.bin`, `CoOps_SlotMachine_RewardSpin.bin`, `README_IMPORT_RU.txt`, `build-report.json`, `plan.json`.

При настройке **«Оригинал»** общие BIN тоже включаются — неизменёнными, для отката прошлых патчей. **Не включай одновременно конфликтующие моды Garden и Graveyard:** AISpawnGrid, Selector и RewardSpin общие. Это отдельный пакет для выбранного режима, а не объединённая сборка сразу двух планов.

## Что важно знать

- **Испытания:** штатный выбор либо принудительно существующее `NoKnockouts`, `NoBaseDamage` или `NoPlayerDamage`. Это не полное отключение заданий. Сохраняются callbacks завершения/сброса и все остальные события. Мгновенного обхода нет: прежний эксперимент сопровождался зависанием таймера.
- **Колесо:** исходное распределение; только монета/мешок/алмаз; только деньги без horde; собственные относительные веса. Они применяются к двум штатным веткам RewardSpin. Денежный выбор не заменяет боссов в составе. Визуальное вращение/tease, размер и факт выплаты не подтверждены игровым тестом.
- **Враги:** изменяются min/max существующих записей. Это лимиты, не точное гарантированное количество; SpawnPoolSize и общие потолки остаются исходными. Добавления новых игровых классов/типов нет.
- **Точки:** A01–A55 — метки проекта, не штатные SpawnID. Используется экспериментальная схема 100xx. Мировые координаты не двигаются. Для Graveyard применяется та же сетка; её работа в этом режиме пока не подтверждена в игре.
- **Служебные волны:** корневые ссылки сохраняются. Graveyard `Wave00` не подменяется первой волной; эвакуация не перенаправляется.
- **Специальные события:** внешние префабы сохранены; редактор не гарантирует устранение всех побочных волн/эффектов.
- AMBUSH-вступление, произвольные новые спавнеры, другие карты, неизвестные версии BIN и экспорт FBMOD не реализованы. Неизвестные исходники отклоняются по размеру/SHA-256.

## Текстовый редактор и сохранение

Блок **«Текстовый редактор плана · JSON»** → «Показать текущий план» → изменения → «Проверить и применить JSON». Неприменённый текст не влияет на сборку. Неверный JSON/другой режим отклоняется без замены плана.

В плане: `mode`, `waves`, `enemyLimits`, `ops`. Подробности: [docs/OPS-EDITOR.md](docs/OPS-EDITOR.md). Кнопка «Скачать план JSON» — резервная копия. Ключ Garden `gw2-timepark-select-v1` сохранён; Graveyard использует отдельный `gw2-timepark-graveyard-v1`. При смене адреса сайта/браузера автосохранение может не перенестись. Старые Garden-планы импортируются с исходными настройками общих ресурсов.

## Загрузка в GitHub

1. Сохрани резервную копию репозитория. Загрузи **содержимое папки `pvz-zaebal` в корень**, включая `graveyard.html`, `originals/`, `data/`, `src/`, `scripts/`, `tests/`, `.github/` и обе готовые HTML-страницы. Не загружай только ZIP или лишнюю вложенную папку.
2. Простой вариант: Settings → Pages → Deploy from a branch → main → /(root).
3. Для автоматических тестов и публикации: Settings → Pages → Source: GitHub Actions. Workflow собирает обе страницы и копирует `originals/` в `_site/`.
4. Сохрани свои `CNAME`, `.gitattributes` и настройки домена. Они не входят в пакет.

Пакет подготовлен для `qu0tas/pvz-zaebal`. Из чата удалённый репозиторий **не изменялся**, Actions удалённо не запускались.

## Исходники и публичность

В `originals/` — **42 предоставленных BIN/XML** с манифестом размеров/SHA-256. Из них каждая страница встраивает пять нужных BIN. Остальные специальные префабы и слои служат материалом разбора и **не включаются автоматически в результат**. Три Graveyard-слоя `_spawns` содержат `AlternateSpawnEntityData`; это само по себе не доказывает связь с AI-точками Axx.

По прямому запросу владельца оригиналы включены в пакет. Публичный репозиторий/Pages раскрывает эти данные, включая base64 в HTML. Перед публикацией проверь право их распространять; никаких прав на игровые ресурсы этот проект не предоставляет. Дополнительные личные выгрузки держи в игнорируемой `local-game-files/`. Сгенерированные тестовые BIN, FBMOD/FBPROJECT и `artifacts/` не коммитить.

## Для разработчика / агента

Python 3.10+, Node 20+, без обязательных npm/pip-зависимостей. Playwright нужен только для дополнительного браузерного smoke-test.

```bash
python scripts/generate_ops_profiles.py --check
python scripts/build.py --check
python -m unittest discover -s tests -v
node tests/bin_builder.cjs
node tests/ops_profiles.cjs
python scripts/verify_generated.py artifacts/ops-tests/garden
python scripts/verify_generated.py artifacts/ops-tests/graveyard
# Необязательно: Python Playwright + Chromium
python scripts/browser_ops_smoke.py --browser /path/to/chromium
```

Для правок: `src/app.js` — формы и план; `src/ops-panel.html` — общие настройки/JSON; `src/bin-builder.js` — запись пяти BIN; `scripts/generate_ops_profiles.py` — каталоги/профили. Затем **`python scripts/build.py`** пересобирает обе HTML. `data/bin-schema.json` и `generate_bin_schema.py` оставлены как исторический профиль трёх Garden-ресурсов; действующие профили — `garden-profile.json` и `graveyard-profile.json`.

Проверки этой версии: 18 Python-тестов, 12 синтетических JS-проверок, 30 проверок действующих профилей, 530 сочетаний группа/состав, полный браузерный путь обоих редакторов и независимое семантическое чтение пяти результатов каждого режима. **Это статические проверки, не тесты игры/Frosty.**
